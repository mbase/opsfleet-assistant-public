## Interpretation rubric semantic-v3

`scenarios.json` contains five drafted paraphrases per playbook, each in three independently initialized cases (45 interpretations). **Independent paraphrase review has NOT_RUN.** A reviewer must check every phrasing against its assertions before the owner records approval. Repetitions use separate conversations and no inherited model context; they are not a statistical claim of independent model errors. The immutable snapshot file is shared across the entire trial.

The whole first request must contain exactly the single declared query and operation, with the declared intent, analysis mode, playbook, filters and report/action effects. Every semantically applicable query field is checked, not only query zero. The fixed-shape product/regional/churn playbooks do not compile a LIMIT, so their inert limit defaults are omitted from comparison. Inactivity_days is omitted only for non-churn product/regional queries; the requested 90-day churn window remains mandatory. No query, real filter, period or report/action effect is omitted by this normalization. Status ordering and inherited versus explicit full authorized brands are normalized; symbolic dates are checked through resolved roles, and source-provenance annotations remain diagnostic. First-semantic PASS/FAIL/NOT_RUN and the final workflow status are separately recorded in sanitized attempts. A repaired successful workflow cannot turn a failed first request into PASS.

Every interpretation must preserve metric/operation, effective item-grain brands/products, statuses, period/current and earlier cutoffs, purchaser denominator, country/state selection, playbook, ordered direction, inactivity window, calculated difference/components, and absence of unintended save/action effects. Each assertion in the manifest is mandatory. Wording may vary. Assertions inspect interpreted choices plus actual compiled/executed semantics and released values, rather than prose alone. Failures or model repairs must be reviewed from the private checkpoint; a corrected final workflow never erases a first model failure. Semantic substitution on any first interpretation fails the case even if a later interpretation repairs it.

The proposed gate is at least 95% of executed, independently reviewed interpretations passing **all** checks, and zero silent scope/population substitutions. Publish attempted/planned/reviewed denominators, provider failures, initial failures and repair dispatches separately. Injected HTTP tests validate this procedure; they do not populate the real interpretation numerator. Human review of public booleans alone cannot assess wording: use restricted private checkpoints without publishing transcripts.

## Warehouse journeys

Nine scenario chains / fifteen turns cover scalar revenue and an independent reference, exact save, process/store recreation, list/read, conversation deletion preview, exact confirmation and replay; ranking, trend, missing-year clarification, scope/PII denial; and all three playbooks. Product IDs are discovered deterministically from two qualifying authorized products at the same snapshot, not chosen by the model. Insufficient products are a data precondition failure, never a scope/date expansion. Regional comparisons declare Texas minus California; country attribution may be unavailable under the existing privacy rules.

All catalog, business, coverage, discovery and independent-reference reads receive the **same** fixed `FOR SYSTEM_TIME AS OF` timestamp at the guarded transport. Public source time-travel availability, retention and owner authorization remain unverified; a missing snapshot blocks the entire warehouse layer before ADC/client construction. The owner must select an available fixed UTC timestamp and attest authorization. Unsupported source/time-travel fails closed; no mutable-source fallback. The scalar oracle and independently authored aggregate SQL/arithmetic for all playbooks use the same guarded adapter/budgets. Ranking/trend journeys check successful bounded state, not independently certified row-by-row numerical equality.

A saved scalar result may legitimately be partial when requested actions have no support. The journey requires exact preserved content/completeness and never upgrades it to complete. Playbook live cases require their declared complete decomposition and same-snapshot oracle; privacy-limited public populations can fail that critical-case gate and must be reported, not silently exempted. Deterministic tests separately validate safe partial behavior.

## Status and accounting

Allowed case outcomes: PASS, FAIL, PROVIDER_FAILURE, BLOCKED_ENVIRONMENT, NOT_RUN. A policy-denial journey can PASS only when denial is its expected result. Unexpected policy denial, exhausted budget, provider error, unavailable snapshot and local-state cleanup failure remain distinct reasons/outcomes in private accounting and public summaries. An unexecuted case has no attempts; unknown billing/cost remains null. No p95 is reported for these small samples.

Each started turn is durable before dispatch. Every model attempt and warehouse job reserves its budget before sending; unknown submission/billing halts scheduling. There is no automatic replay after an interrupted dispatch. Resume uses explicit scenario IDs and the same manifest/state/run identity; completed and failed cases are skipped. Use a new run ID for an intentionally repeated experiment and publish both runs.

The candidate limits are 240 provider calls, 40 warehouse executions, 5 GiB billed bytes and 2,700 active seconds per layer/run, with the existing smaller per-turn ceilings. The preflight shows the exact configured upper bound for a selection. For all 45 interpretations: nominal 90 model calls, hard ceiling 240, zero live warehouse calls/bytes. For all warehouse scenarios: nominal about 15 model calls and at most 30 ordinary/reference jobs (actual recovery varies); hard ceilings are 90 provider calls / 40 jobs / 180 dry runs / 5 GiB / 2,700 active seconds for all fifteen turns, and are printed by dry-run. Costs are unknown until the owner supplies a reviewed conservative per-call price/token reservation and total limit. Per-call dollar reservations depend on that external price ceiling; the client cannot force the provider's actual tariff. Unknown or excessive reported cost stops further dispatch after that response. Use an account-side spend cap for a provider-enforced monetary guarantee.


## P5-R2 inventory policy part5-inputs-v2

Freeze and verification share one filesystem inventory, independent of Git tracking/ignore status. It covers `src/`, `tests/`, `config/`, `scripts/`, `.github/`, declared root dependency/config files, root Python/test/build configuration, and executable files/packages elsewhere in the source tree. Added, removed, changed and symlinked inputs require a new freeze. When `.git` exists, HEAD/tree and the recorded tracked application diff hash must also match. Source copies without `.git` still require the exact file set and hashes.

Known environments, runtime, build/egg-info and cache directories are excluded. Narrative review/report files, this manifest and validation `results/`, `history/`, `runs/`, `private/` are intentional identity exclusions; source/test configuration and executable inputs elsewhere are not. These exclusions are declared by code in `evaluation_inventory.py`, itself a frozen input. Installed dependency identity remains the separate constraints/install layer.

The supported `scripts/run_live_evaluation.py --manifest ...` entry point loads the stdlib-only verifier by filename before avoidable application imports. Manifest help exits without application imports. This detects identity drift; it is not a sandbox for hostile Python startup/site customization or a malicious local operator. The in-process validator rechecks the inventory, and the owner-run finalization checks it again. The reviewed pre-fix candidate/results are preserved byte-for-byte in `history/pre-review/`; they are not evidence for the revised freeze.
